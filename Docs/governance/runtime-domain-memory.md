# Runtime Domain Governance — Memory

## Purpose

The `memory` domain preserves continuity, provenance, recall, receipts, summaries, and indexed runtime state.

In LeeWay, memory is not decorative context. It is evidence-bearing state and must remain governed by standards law.

## Canonical Rule

> Memory may be appended locally by the runtime, but canonical memory identity, provenance rules, and retention law originate from LeeWay Standards.

## Governing Agents

- `memory-warden-agent`
- `attestation-marshal-agent`
- `leeway-memory`
- `memory-mcp`

## Responsibilities

- provenance-bearing continuity
- receipt-linked memory writes
- retention and compaction policy
- trusted recall and retrieval
- separation of canonical truth from speculative or low-trust notes

## Allowed State

- chats
- indexes
- summaries
- receipts
- registry snapshots
- project state

## Forbidden State

- unattributed memory mutation
- silent deletion of canonical memory
- trust laundering where speculative memory is presented as validated truth
- runtime-private agent identities stored as if they were canonical LeeWay identities

## Minimum Memory Law

- append-only by default
- mutate only with explicit authority and evidence
- delete only under documented retention rules
- preserve trust level and provenance markers where available

## Relationship To LeeWay VS Code

LeeWay VS Code may store memory artifacts under local runtime folders, but those artifacts remain subordinate to the governing memory law declared by LeeWay Standards.
