# Tablet Product Lifecycle Acceptance and Qualification Checklist

This checklist is a proposed qualification aid, not a declaration of existing operational proof.

## Workspace foundation
- [ ] Product workspace has a stable product ID and accountable owner.
- [ ] WHO, WHAT, WHEN, WHERE, WHY and HOW fields exist and are maintained.
- [ ] Product scope, assumptions, risks, decisions and acceptance criteria are linked.
- [ ] Identity, permission and environment boundaries are established.

## App relevance and adapter qualification
- [ ] Every Tablet app has a declared functional reason and role.
- [ ] Each applicable app handoff uses a documented interface/adapter.
- [ ] Input/output, authentication, permission scope, failure behavior and version are declared.
- [ ] Missing adapters are visible as NOT_CONFIGURED/UNKNOWN; no simulated success.
- [ ] App roles are verified against actual repository or endpoint behavior.

## Stage gates
- [ ] Idea/discovery: problem, user/customer, assumptions and initial evidence.
- [ ] Market/business: value proposition, customer research, pricing/business hypotheses and risks.
- [ ] Design: requirements, architecture, traceability and acceptance tests.
- [ ] Build: versioned source/artifacts, task traceability and environment.
- [ ] Qualification: tests, contrary evidence, security/failure/recovery checks and review.
- [ ] Commercial launch: package, documentation, terms, claims, delivery/support and approval.
- [ ] Production: release identity, deployment authorization, monitoring, rollback, support and recovery.
- [ ] Replication/training: reproducibility, installation, onboarding, training and review evidence.
- [ ] Improvement: sourced feedback, change impact, requalification and lifecycle status.

## Inspection sequence
- [ ] Model
- [ ] Work
- [ ] Test
- [ ] Contrary Evidence
- [ ] Review

## Proof and custody
- [ ] Evidence references identify source, scope, version and relevant context.
- [ ] Receipts exist only where actually generated by Receipt Authority or a documented custody process.
- [ ] Veritas results are based on declared verification criteria and actual evidence.
- [ ] Physical/hardware claims have appropriate measurements; source tests alone are not physical proof.
- [ ] Status and gaps are reviewed and updated.

## Replication pack
- [ ] Versioned source/build/package and dependencies.
- [ ] Configuration template and environment prerequisites; secrets excluded.
- [ ] Installation, deployment, rollback, recovery and maintenance instructions.
- [ ] User/operator/customer documentation and training material.
- [ ] Commercial collateral and claims reviewed against evidence.
- [ ] Replication and competency/recovery evidence captured.
