# Runtime Domain Governance — Patches

## Purpose

The `patches` domain governs repair artifacts and mutation packages generated by structured engineering loops.

## Canonical Rule

> Patches must be governed repair instruments with attributable ownership, not blind mutation payloads.

## Responsibilities

- preserve before/after intent for change sets
- bind patch application to approvals where required
- maintain rollback and recovery pathways
- link patches to validation outcomes and receipts

## Allowed State

- patch files
- mutation plans
- rollback artifacts
- repair-loop outputs

## Forbidden State

- anonymous patch injection
- destructive patching without recovery path
- patch application that bypasses write-policy checks

## Minimum Law

- approval gates for high-risk patch operations
- receipt-required patch apply events
- validation proof before promotion to canonical state
