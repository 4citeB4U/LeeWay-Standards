# Runtime Domain Governance — Reports

## Purpose

The `reports` domain carries verification output, compliance summaries, audits, packaged validation evidence, and developer-readable runtime truth.

Reports exist so the runtime can prove what it did, why it did it, and whether the action was compliant.

## Canonical Rule

> Reports are the public evidence surface of the runtime. They may be generated by LeeWay VS Code, but they must remain attributable to LeeWay Standards governance rules.

## Governing Agents

- `attestation-marshal-agent`
- `leeway-validation`
- `leeway-testsprite`
- `ClerkArchive`

## Responsibilities

- validation summaries
- compliance reporting
- packaged runtime evidence
- release and repair audits
- developer-facing runtime truth without leaking secrets

## Allowed State

- compliance summaries
- packaged validation logs
- repair reports
- verification receipts
- audit artifacts

## Forbidden State

- secret-bearing reports
- unverifiable claims presented as compliance truth
- report generation without traceable runtime ownership
- silent rewriting of historical evidence without audit annotation

## Minimum Reporting Law

- redact secrets automatically
- include attributable source or agent where possible
- preserve timestamps and evidence context
- clearly distinguish verified, partial, and speculative outputs

## Relationship To LeeWay VS Code

LeeWay VS Code may generate and store runtime reports locally, but those reports remain constitutionally governed by LeeWay Standards and should reference the canonical runtime source where relevant.
