# Module 6: One-Click Sovereignty

The ultimate goal of the Sovereign Architect is to build systems that exist entirely within a controlled, independent environment. We must move away from fragile, multi-cloud setups and embrace unified deployment.

## The Canonical Deployment Stack
As detailed in the Sovereign Architect’s Handbook, the sovereign ecosystem now relies on the canonical LeeWay VS Code stack governed by LeeWay Standards.

1. **The Host (LeeWay VS Code):** The primary sovereign execution surface and user environment.
2. **The Runtime Planes:** `agent-lee`, `workspace`, `safety`, `sandbox`, `knowledge`, `logs`, `memory`, `patches`, and `reports`.
3. **The MCP and Agent Plane:** Governed MCPs, host-linked agents, and verification surfaces.
4. **The Visual Intelligence Plane:** LVIS for reconstruction, repair, packaging, and project integration.

## Docker Orchestration
Sovereignty means portability. The entire ecosystem is deployed using `Docker Compose`.

### Why Docker Compose?
*   **Isolation:** Runtime components can be packaged and validated without contaminating the main developer profile.
*   **One-Click Launch:** Users and architects can stand up the governed runtime and its supporting services consistently.
*   **Self-Healing:** Runtime surfaces can be restarted or repaired without losing the constitutional control model.
